# Cost controls

MohitOS is built by and for a cost-sensitive solo operator. The standing policy: free tier first, OSS first, cheap models first, and every paid action behind an explicit gate. Guardrails are features, not afterthoughts.

## Model routing by cost

- **Cheap by default.** The LLM layer exposes a cheap-model path (routed through OpenRouter) that handles the high-volume work: classification, feedback routing, caption rewrites, summaries. Escalation to stronger models is reserved for the places where brand voice precision actually pays, like final content drafting.
- **The same policy applies to the operator console.** When I build with Claude Code, the expensive model does planning, architecture, and verification; implementation is delegated to cheaper subagents working against defined interfaces. This is a written working rule, not an ad hoc habit.
- **Free local fallbacks exist on the render path.** Voiceover runs on ElevenLabs when quota allows and local Kokoro TTS on the free path; the pipeline is built so the free path is a first-class option rather than a degraded mode.

## Paid renders sit behind a human tap

Content formats are classified into autopilot tiers:

- **Green** formats (text-clean work like carousels and standard shorts) may be auto-generated by the morning sweep with no tap.
- **Yellow** formats stay behind a human tap. Generative video animation is yellow specifically because each render is a paid fal.ai call. The tier classifier ships with the code, so the droplet and the Mac enforce the same policy.
- Green means auto-generate only. **Publishing is never auto-approved at any tier.** The publish gate is a separate system (see [human-in-the-loop.md](human-in-the-loop.md)) and autopilot cannot reach around it.

This tiering came from a real incident: an agent build once flipped all formats to green, which would have let the 9am sweep spend money and quota with zero taps. The correction became policy: unattended paid actions require an explicit opt-in, and the default is the free path.

## Daily caps and quota math

- **Auto-generated shorts are capped at 2 per day** (an environment-variable knob, default 2). Overflow does not silently drop: extra ideas escalate to a normal Telegram nudge, because human taps are deliberately uncapped.
- The cap is derived from actual quota math, not vibes: the free ElevenLabs tier is roughly 10k characters a month, which is about 20 reel voiceovers. Three unattended shorts a day would burn the month's quota in a week, and a dead quota fails ugly (silent-fallback audio on reels that then stall in the queue). Two a day keeps autopilot inside the free tier with headroom for manual runs.
- Cold-email tooling in the same codebase carries its own spend guardrail (a $20/month cap on that lane).

## Infrastructure economics

- **Self-hosted OSS over subscriptions where it holds up.** Postiz (social scheduling) on a small droplet replaces a per-seat scheduler subscription. pg-boss inside the existing Postgres replaces a hosted queue. The Telegram bridges are a couple of hundred lines of polling code on a $6/month box.
- **Kill redundant spend on sight.** A self-hosted Cal.com box was decommissioned when booking turned out to be covered by an existing tool, and an orphaned droplet was destroyed during a cleanup pass. Small numbers, but the habit is the point: the bill gets audited like code.
- Steady state: a couple of droplets at $6 to $12 a month each, Supabase and Vercel free tiers, and metered AI APIs whose spend is bounded by the gates above.

## The principle

Every recurring cost needs an owner decision, and every metered cost needs a cap or a tap. The system is allowed to be ambitious precisely because it is not allowed to be expensive by accident.
